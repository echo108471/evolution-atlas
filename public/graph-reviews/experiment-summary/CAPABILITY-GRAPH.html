Iterative capability graph experiment

For the readable cross-experiment synthesis, see Experiment summary and lessons.

The September 6 experiment replaces a fixed semantic depth with a bounded investigation loop: choose evidence, inspect it, revise a candidate graph, and investigate again. It is an experimental successor to two-level induction, not a new canonical map or a viewer integration.

What the model controls

The model may create broader parents, split or merge existing nodes, rename them while preserving identity, remove unsupported nodes, and reparent children. Containment can have multiple parents and uneven depth. Dependency is a separate directed relationship, not an implicit parent. The first relationship vocabulary is contains and depends_on; this does not claim to enumerate every relationship in software.

There is no capability count, maximum semantic depth, or maximum share of the repository that a capability can cover. Round and retrieval budgets constrain work, not meaning. An additional parent must explain a shared outcome; another round does not require another layer. Earlier interpretations remain open to revision from above and below.

Evidence and state boundaries

The seed is the 29 leaves of an earlier blind induction, alphabetically reidentified with the old parent labels and positional IDs removed. This tests growth and revision from existing local interpretations. It does not independently rediscover those leaves from raw source, and their original grouping and summaries may still bias the result.

Each round has three steps:

  1. A planner sees the current graph, a catalog of all 605 cached reading subjects, and safe paths at the pinned head. It requests readings, text searches, and exact source windows.
  2. A deterministic broker retrieves up to 12 readings and six source windows, within 24,000 serialized evidence bytes. Source gets reserved capacity. Search matches cached reading text and paths; newly found paths can be requested in the next round.
  3. A decision model sees the graph and retrieved evidence, without planner prose. It produces an atomic patch with citations, reviewed-node IDs, uncertainty, and a local continuation decision. A bounded correction call is allowed after validation rejection.

Source inspection uses immutable Git blobs at the seed's head or a cached reading's historical revision. A source citation includes commit SHA, blob SHA, path, line interval, and truncation. Windows are at most 79 lines and 5,000 text bytes; blobs above 1 MiB are omitted. Sensitive paths, symlinks, and binary content are excluded. No working-tree file contents are sent. Source content is recorded as observed; summaries and graph claims are candidate interpretations.

The parser rejects unknown citations, duplicate IDs/relationships, dangling endpoints, self-edges, and containment cycles. Dependencies require a retrieved source citation. Those checks establish reference integrity, not semantic correctness: a source file can be cited without proving the particular relationship. New claims can cite only the current round's retrieved evidence. Unmodified seed claims retain their original provenance.

Every round saves its requests, raw provider responses, retrieval results, rejected attempts, patch, and resulting snapshot. The seed is untouched. Exact-request fingerprints protect resume/replay; existing artifacts cannot be overwritten with different content. The final artifact carries the full reading registry and explicit unreviewed node IDs. Generated artifacts must live in ignored local paths.

Investigation agenda

local-v1 let a local decision stop the entire loop. It stayed in one neighborhood and stopped after reconfirming the same source. agenda-v2 additionally exposes previously reviewed nodes, unreviewed nodes, and prior investigation questions. The planner can compare roots, challenge a relationship, or move to an unreviewed area. A local stop does not stop the session while unreviewed nodes and a round budget remain.

The agenda does not force coverage within a small budget or force a deeper graph. A budget stop leaves outstanding work explicit. A reviewed ID is the model's accounting statement, not an independent finding that its boundary is correct.

full-v3 adds a coverage queue of up to four unreviewed nodes per round, including newly created nodes. Queue membership is not a grouping suggestion. The broker reserves one available cached reading per queued node before the remaining model-ranked requests. The model must account for each queued node, including explicit deferral where evidence is insufficient. Once coverage is complete, two whole-map reconciliation rounds investigate broader parents and redundant or misplaced relationships. Newly added nodes still require coverage before completion. A 24-round ceiling bounds this full run; it is not a depth target.

The current evaluation is Eugene's yes/no judgment of the frozen output, as requested. The local review report exposes every node and edge with separate unrated ballots, notes, evidence links, and a JSON export pinned to the graph fingerprint. These judgments are not inputs to this discovery run. Full coverage means the queue was accounted for, not that every claim was confirmed in source or that all 605 reading texts were reread.

Alternative comparison and historical evidence

The follow-up alternatives-history-v1 condition compares proposals without modifying the frozen full-run graph. Eugene's supplied judgments are saved separately in the ignored full-run review directory: 28 accepted nodes, two unrated nodes, and seven accepted edges. Neither those verdicts nor their notes are loaded by the comparison runner.

Four targeted cases use the annotated node IDs only. Two other IDs are selected by sorting SHA256(node ID), excluding the annotated IDs. They are called blind-selection cases, not a held-out repository: the existing map, prompts, and earlier investigations still carry repository knowledge. Each case starts independently from the same frozen graph; no prior case's answer or cohort label is included in its prompts.

Each case uses three stages:

  1. Select cached readings to challenge the focus boundary and relevant neighboring nodes.
  2. Inspect a historical path index, then select up to six source windows. The index exposes changed paths present at selected commits and their first parents, including deleted implementations absent from the pinned head. It caps each revision at 70 candidate paths and records omissions. First-parent inspection is explicit and opt-in; it does not trace all merge parents, rename lineage, or the complete history.
  3. Compare two to four alternatives, choose one, and name its strongest rival. Alternatives can retain separate nodes, propose an umbrella or split, identify a dependency, describe implementation history, or remain uncertain. Exact proposed members/relations are prose at this milestone, not automatically applied graph edges.

A selected dependency needs retrieved source. Selected implementation history needs source at two distinct revisions, but this only establishes reference coverage, not replacement order or semantic continuity. No stage requires a new layer. Calls and raw responses are persisted before validation, with at most one repair per stage and exact-request replay. Retrieval remains bounded to 12 readings, six source windows, and 24,000 serialized bytes per case. The report displays the chosen interpretation, alternatives, weaknesses, unresolved questions, and exact retrieved evidence; no new judgments are prefilled.

Explicit structures and broad human review

structures-v2 keeps the same six case IDs and frozen baseline, but represents each structural alternative with explicit new nodes, retired nodes/edges, and parent-to-child containment links. Each alternative is validated against a separate candidate snapshot. An umbrella may use an existing parent or add one, but cannot delete any existing child. Splits and merges must identify their replacements. Cycle, dangling-edge, and citation checks remain structural safeguards, not semantic acceptance.

Dependencies and implemented_by observations are proposed separately from the structural choice. A capability can remain distinct, belong to a parent, and depend on another node. Implementation links record only source-supported existence at specified revisions; they cannot claim an exclusive era or replacement order. They are not automatically applied to the baseline graph or combined across independently generated cases.

The broker protects two current and two historical source slots, then fills up to six total windows from remaining ranked requests. Known current source anchors on the focus node are available as fallbacks. Current paths that are missing or wrong do not count as retrieved evidence. Reading text receives at most 9,000 serialized bytes and each source window at most 1,800 text bytes, with a 24,000-byte overall ceiling. This trades excerpt depth for coverage across periods; it does not guarantee the right historical mechanism was selected. Omissions and absent-period gaps are preserved.

A fourth, separate model call audits the selected structure and optional links against the same retrieved evidence, reporting supported, partial, or unsupported with concrete issues. It is not independent ground truth and cannot compensate for missing source. The user-facing report leads with the proposed arrangement and brief model checks; alternatives and evidence are optional details. Eugene's feedback is broad plausibility, not a requirement to approve individual citations or supply a target taxonomy.

Run the same comparison command with a new ignored output directory and --protocol structures-v2. Each of four stages permits at most one saved repair request. Replay requires the same protocol and arguments.

Whole-project and data-lifecycle coverage

The whole-project condition starts from the frozen 30-node full-run graph, not the six case reports. All existing nodes enter a coverage queue; new nodes also require accounting. The first investigation prioritizes source collection, ETL, embeddings, identity/schema, backend catalog services, delivery/cache, and frontend catalog loading. This is an explicit coverage priority requested by Eugene, not a target group or supplied taxonomy. The run then covers the remaining nodes and requires two combined-map reconciliation rounds, within a 14-round safety budget. A budget stop leaves unreviewed IDs explicit.

Each round selects readings, refines retrieval using pinned current/historical path indexes, then produces a cited atomic patch against the combined candidate graph. Per-node model assessments distinguish supported, partial, and unresolved; supported requires retrieved source but still needs a semantic relevance judgment. Unrelated evidence is explicitly not support for retaining a node. The broker allows 12 readings and eight source windows within 46,000 serialized bytes, retaining the 79-line/5,000-byte per-window limits.

The preliminary whole-project-v1 run exposed attention drift: the full graph's first professor-insights node dominated retrieval even when data/ETL IDs were queued. Relevant baseline source anchors were appended after other requests and could be starved. Its partial artifacts are retained separately. whole-project-v2 puts the queued node objects first in planner context, reduces the remaining graph to a navigation catalog, prioritizes known current anchors in the broker, and adds one bounded follow-up for weak priority-area assessments after the first round. The decision model still sees the full combined graph.

The broad report displays the entire candidate map as expandable capabilities, with the priority areas linked for navigation but not presented as an invented group. It asks only for overall plausibility; individual ballots are omitted. Exact evidence and every patch remain available in optional detail. Neither coverage nor a richer display establishes semantic completeness or guarantees the model will propose an umbrella.

Matched-evidence umbrella anchoring experiment

umbrella-ablation-v1 isolates the presence of starting containment links. Both conditions receive the same 47 capability IDs, names, summaries, evidence IDs and 11 dependencies from the frozen whole-project ETL output. The linked condition also sees the 17 existing containment links; the unlinked condition does not. Both strip old rationale, origin and round metadata. The model receives neither the condition label nor owner judgments. Names and descriptions remain potential anchors: this is not de novo discovery or an ablation of all prior interpretation.

Evidence selection happens once before inference, independent of condition: one directly cited source excerpt per node (prefer pinned head, otherwise history) and one directly cited reading when available, deduplicated without shortening the saved text. The resulting packet has 40 items, 87,915 serialized bytes, and source excerpts for 39 of 47 capabilities. It is the same packet in every pass; this tests formation under matched evidence, not adaptive retrieval or complete coverage of all 605 cached readings. No fresh source request is made.

Two repeats use counterbalanced condition order. Each trajectory has a discovery pass followed by a challenge/reconsideration pass. The same prompt invites broader outcomes and allows abstention, existing-parent reuse, parents above parents and multiple parents, with no target depth, count, or size. Seed nodes and dependencies are held fixed for this preservation test; containment can change. New nodes must be parents with at least two seed descendants. This intentionally restricts the editing vocabulary to test upward organization, not the full discovery architecture. It cannot establish that an unrestricted model spontaneously prefers umbrellas.

Each response is saved before validation, with exact request fingerprints and at most one structural repair. The cost guard is not an absolute billing cap: a final in-flight request or a request with no returned usage can incur additional cost. No accepted baseline is patched.

Structural measures include preserved seed details, original links retained or recovered, depth, parents spanning at least two original roots, and label-independent co-umbrella pair overlap. Competing scopes and parent reuse (umbrella-scopes-v1)

The follow-up freezes a model-proposed set of alternatives before retrieving extra evidence. It tests whether that evidence changes boundary judgments, whether existing parents can express the outcome without a duplicate node, and whether decisions remain similar when alternative order is reversed. Owner judgments remain held out.

Case selection is mechanical, not a new owner taxonomy: form connected components of overlapping seed-descendant sets in every prior new-parent proposal. Select the two components with the most distinct memberships (hash-ID tie break), then the remaining component whose closest existing covering parent has the most additional responsibilities. This selects professor evaluation, grade insight, and ETL loading from six neighborhoods. It is a selected-disagreement pilot, not a representative repository sample.

For each case, one call receives the compact baseline graph, prior scope hypotheses without run counts or verdicts, the neighborhood's existing evidence, pinned-head paths, and the cached reading title catalog. It proposes three to five alternatives, including unchanged structure, existing-parent reuse, and a new parent. It also requests up to six source windows and four readings that could discriminate among those hypotheses. The deterministic broker uses the pinned Git revision and a 28,000-byte retrieval allowance. Exact-ID duplicates of the old packet are excluded from enrichment; different windows can still overlap in source content. Omitted requests are retained as explicit gaps.

Each frozen alternative set is judged four times: existing versus enriched evidence, each in forward and reverse order. Condition execution order is counterbalanced. The judge sees no earlier verdict, planner weakness, or run provenance. Alternative labels and descriptions still carry framing. Each judgment must assess every alternative and compare every proposed parent with an existing seed; abstention and a missing-alternative description are allowed. A same-model judge is not independent ground truth. One call per evidence/order cell cannot separate order effects from sampling variability.

This preservation test freezes seed descriptions and all original links. Alternatives only add containment or broader parents. No graph is automatically applied. Existing parent reuse can be interpretive only, with the same topology as the unchanged baseline; such choices are not independent structural alternatives. A model wanting to revise a seed description or remove an old edge must defer that change. These constraints can themselves affect the scope decision and are not the intended unrestricted architecture.

There are no automatic repairs or transport retries. Every provider response is saved before validation, and a rejected response remains a failed cell rather than a regenerated semantic decision. A saved request without a response stops continuation until its provider outcome is reconciled. The input preflight is 190,000 characters; output limits are 6,000 tokens for planning and 4,300 for judgment. Recorded usage of $1.50 stops the next request, not an in-flight charge. Raw observations, model hypotheses, and model judgments remain separate in ignored local outputs.
