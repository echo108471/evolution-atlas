# Coordinated and multi-phase work

Use this when work spans independent areas, several implementation phases, a
skill change that needs behavioral evaluation, or a handoff that must preserve
current state. Keep ordinary focused tasks in their existing playbooks.

## Set the work boundary

Ground the active source and settle consequential design questions before
writing an execution checklist. For a multi-phase task, record the intended
outcome, dependencies, owner and file boundary for each slice, and the
observable evidence that closes it. Keep the checklist temporary in the
conversation or an ignored scratch path unless the user asks for a durable
project plan.

Delegate only bounded work that can proceed independently. Give each worker a
clear input, file or investigation boundary, and a concise return shape. Read
the actual returned evidence and inspect every integrated change yourself.
Keep shared files and runtime-driving sessions under one coordinator unless
the work is explicitly isolated.

## Change and evaluate skills

Use the available skill-creator guidance when authoring a Codex skill. Keep the
entrypoint concise and put conditional procedures in linked references. Check
that names, descriptions, links, and scope are discoverable.

When a skill or prompt changes agent behavior, evaluate it with a realistic
request and the minimum needed source context. Review the resulting behavior
and artifacts, not just the wording or a validator's success. Keep evaluation
artifacts isolated and label their limits. Do not promote an evaluation into a
claim about general productivity or quality.

## Resume work with evidence

For a pickup, inspect the current working tree, branch, active process or
browser state, and saved artifacts. Use the conversation or prior summary to
locate decisions and open questions, then verify those against current source.
Preserve explicit user constraints and already completed checks; rerun checks
when the source or runtime state changed.

## Finish the coordination

Report completed slices, their evidence, unresolved dependencies, and work that
remains unverified. This workflow does not authorize external messages,
publication, deployment, automatic scheduling, or automatic pull-request
landing.
